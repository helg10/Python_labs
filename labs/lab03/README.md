Після запуску програми через Uvicorn:
```
uvicorn main:app --reload
```
Сервер розгорнеться локально за адресою `http://127.0.0.1:8000`.

## 1. Як взаємодіяти з API
Використаний у роботі FastAPI надає декілька інтерактивних інструментів для взаємодії з кінцевими точками API:

#### A. Інтерактивна документація (Swagger UI)
- **URL**: http://127.0.0.1:8000/docs
- Як користуватися:
1. Перейти за URL у будь-якому браузері
2. Відкрити будь-яку кінцеву точку (наприклад `GET /records`)
3. Натиснути кнопку **"Try it out"**
4. Зваповнити (якщо потрібно) Query запити або вміст JSON
5. Натиснути кнопку **"Execute"**, щоб надіслати запит, отримати відповідь або переглянути всі можливі заголовки, статуси відповіді

#### B. Алтернативна документація (ReDoc)
- **URL**:http://127.0.0.1:8000/redoc

## 2. Довідка по кінцевих точках
### Базовий URL
`http://127.0.0.1:8000`

### Категорія (`/categories`)

#### 1. Вивести всі категорії
- Метод: `GET`
- Шлях: `/categories`
- Відповідь: `200 OK`
- Приклад відповіді:
```
[
    {"id": 1, "name": "logs"},
    {"id": 2, "name": "backup"},
    {"id": 3, "name": "archive"}
]
```
#### 2. Створити категорію
- Метод: `POST`
- Шлях: `/categories`
- Приклад запиту користувача:
```
{
    "name": "Audit Logs"
}
```
- Відповідь: `201 Created`
- Помилки: `409 Conflict` якщо категорія вже існує
#### 3. Видалити категорію
- Метод: `DELETE`
- Шлях: `/categories/{category_id}`
- Відповідь: `204 No Content`
- Помилки: 
    - `409 Not Found` якщо id неіснує
    - `409 Conflict` якщо категорія містить пов'язані з нею записи (`ON DELETE RESTRICT` обмеження в метаданих таблиці)

### Записи (`/records`)

#### 1. Фільтрувати і вивести записи
- Метод: `GET`
- Шлях: `/records`
- Відповідь: `204 No Content`
- Query параметри:
    - `category_id` (int, > 0, необов'язковий)
    - `status` (str, необов'язковий)
    - `min_value` (float, ge=0 (від 0), le=100 (до 100), необов'язковий) - Мінімальне значення `value`
    - `q` (str, min 1, max 120 символів, необов'язковий) - Пошук підрядка всередині `title`
    - `limit` (int, default=20, min=1, max=100) - Довжина сторінки
    - `offset` (int, default=0, ge=0) - Кількість рядків, яку потрібно пропустити
- Приклад запиту:
```GET /records?category_id=1&status=new&min_value=10&q=system&limit=10&offset=0```
- Відповідь: ```200 OK```
#### 2. Отримати запис за id
- Метод: `GET`
- Шлях: `/records/{record_id}`
- Відповідь: `200 OK`
- Помилки: `404 Not Found` якщо запису не існує
#### 3. Створити запис
- Метод: `POST`
- Шлях: `/records`
- Приклад запиту користувача:
```
[
    {
        "code": "V12-01",
        "title": "Вимірювання сховища 01",
        "category_id": 1,
        "value": 90.0,
        "status": "new"
    }
]
```
- Відповідь: `201 Created`
- Помилки:
    - `404 Not Found` якщо `category_id` не існує
    - `409 Conflict` якщо `code` не унікальний
#### 4. Замінити запис (повне оновлення запису)
- Метод: `PUT`
- Шлях: `/records/{record_id}`
- Приклад користувацького запиту (всі параметри повинні бути заповененими):
```
{
  "code": "string",
  "title": "string",
  "category_id": 1,
  "value": 100,
  "status": "new"
}
```
- Відповідь: `200 OK`
#### 5. Видалити запис
- Метод: `DELETE`
- Шлях: `/records/{record_id}`
- Відповідь: `204 No Content`
#### 6. Масове створення записів
- Метод: `POST`
- Шлях: `/records/bulk`
- Відповідь: `204 No Content`
- Приклад користувацького запиту (список, який містить 1-100 об'єктів):
```
[
    {
        "code": "V12-01",
        "title": "Вимірювання сховища 01",
        "category_id": 1,
        "value": 90.0,
        "status": "new"
    },
    {
        "code": "V12-02",
        "title": "Вимірювання сховища 02",
        "category_id": 2,
        "value": 60.0,
        "status": "in_progress"
    }
]
```
- Відповідь: `201 Created`
- Помилки: `409 Conflict` якщо дані дублюються в бд
